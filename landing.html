Frequently Asked Questions

What does TEOS scan for?

121 detection rules across 4 layers: 64 core rules (secrets, injections, malware, crypto miners, data exfiltration), 29 Solana rules (program security, account validation, authority checks), 10 EVM rules (reentrancy, flash loans, access control, oracle manipulation), and 8 banking rules (CBDC ledger manipulation, SWIFT/ISO 20022, FIX protocol, front-running, reserve key leaks, CBE/FRA dual-mandate).

How do I scan code from the terminal?

Install the CLI (node teos.js scan <file>) or pipe code directly (cat script.sh | node teos.js scan). Results include verdict (ALLOW/WARN/REVIEW/BLOCK), risk score (0-100), and per-rule findings.

Is there a desktop app?

Yes — Extensions Desktop (Beta) is an Electron app with system tray monitoring, background health polling, and native OS notifications for BLOCK verdicts. Run cd desktop && npm start to launch.

Can I scan GitHub PRs automatically?

The browser extension injects a "TEOS Scan" button on GitHub file views. The VS Code extension adds editor context menu commands. Both send code to the TEOS risk engine and display results inline.

What does a BLOCK verdict mean?

BLOCK means the code matched a critical rule (e.g., hardcoded secret, crypto miner, data exfiltration) with high confidence. The engine uses both deterministic rules and heuristic suspicion scoring to reach this verdict.

Is my code sent to an external API?

Yes — the CLI, desktop app, and extensions send code to agent-code-risk-mcp-production-b97d.up.railway.app for scanning. No code is stored after scanning. Self-hosted deployments are available on the Enterprise plan.

How is TEOS different from a linter?

Linters check syntax and style. TEOS checks security, supply-chain risk, blockchain program safety, and prompt injection — things a linter cannot detect. The engine includes the REVIEW verdict for cases requiring human judgment.
