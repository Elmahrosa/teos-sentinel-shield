01 Merged
Monolithic Consolidation

Consolidated Monolithic Core

All TEOS subsystems — Sentinel Shield, agent orchestration, memory, RAG, MCP, tools, webhooks, analytics — now live inside a single deployable unit. No microservice fragmentation. One repository. One deployment. One audit surface.

  • 17 modules consolidated into src/ — agents, analytics, api, auth, core, database, mcp, memory, middleware, rag, reasoning, security, templates, tools, webhooks
  • Single Python 3.11+ process on FastAPI with asyncpg, Redis, and PostgreSQL
  • Eliminated inter-service network latency — all calls are in-process function invocations
  • Unified error handling, logging, and Sentry instrumentation across all modules
  • Docker Compose single-service deployment — one container, one health check, one scaling unit

02 Live
Pre-execution Firewall

Deterministic Sentinel Shield

A fail-closed pre-execution firewall that scans every AI action before it runs. Not probabilistic. Not ML-based. Deterministic rule enforcement: 27 named rules across three scan engines. Every tool call, every MCP invocation, every agent action passes through Sentinel before execution.

  • Fail-closed: network errors, timeouts, or Sentinel downtime all default to BLOCK — never fail-open
  • Three scan engines: input content, tool parameters, and output filtering
  • Every tool input and output passes through Sentinel — no exceptions, no bypass paths
  • Verdicts: BLOCK (halt + human notification), WARN (log + proceed with audit), ALLOW (proceed)
  • Deployed on Railway with PM2 sidecar — self-hostable on customer infrastructure

03 Active
Governance Architecture

Dual-Key Sovereign Control Plane

No single-point-of-failure for governance overrides. Every critical governance action requires dual authorization — the AI system proposes, a human operator approves. This is not a feature; it is the architectural foundation of sovereign control.

  • BLOCK verdicts require human confirmation — AI cannot autonomously halt or destroy
  • JWT authentication with HS256 signing — no single stolen token compromises the system
  • API keys and secrets never stored by Elmahrosa — customer-controlled per Sovereignty Standard §01
  • Audit logs are immutable and customer-controlled — webhook delivery via HMAC-SHA256 signatures
  • Law over Code: regulatory obligations override technical defaults when they conflict
